# 注册前异常拦截

日期：2026-11-07。状态：已实现并通过回归验证，尚未发布。

## 问题和目标
当前跨 IP 浏览器特征规则仅观察，导致批量账号仍能发送验证码和注册。将服务端确认的异常在邮件入队之前拒绝，持久标记邮箱，防止切换来源重试。已有账号的正常登录不走新用户创建规则。

## 规则
- 命中活动来源封禁、成功注册额度，或同特征在统计窗口内同时达到账号数和不同 IP 数阈值，拒绝注册。
- 与至少两个已明确人工封禁的批量注册账户、至少两个 IP 关联的特征，继续拒绝。
- 单独相似特征、缺少 cookie 或基础设施故障不永久标记邮箱。基础设施故障拒绝本次操作。
- 邮箱按现有收件箱别名规则规范化，标记持久保存，默认不自动过期。后续来源变更或关闭自动检测不能绕过已有邮箱标记。
- 邮件验证码、OAuth 待完成注册验证码在 CAPTCHA 和邮件调用前检查；最终创建用户在事务锁内再次检查。事务失败仍保留邮箱标记。
- 对外统一 HTTP 403 / REGISTRATION_UNAVAILABLE / 暂时无法完成此操作，不返回具体原因或 Retry-After。具体原因仅用于数据库审查。
- 不扣余额、不删除账户，不影响其他工作区未发布改动。

## 验收
正常注册继续；异常来源零邮件调用；规范化邮箱换 IP/别名重试仍拒绝；并发注册不能突破额度；事务回滚保留标记；已有账号登录行为保持；数据迁移可应用。

验证：service/handler/repository 单元回归、PostgreSQL 注册集成及跨 IP 并发拦截测试、验证码入口顺序测试、go vet、前端注册防护与 i18n 8 项测试均通过。分支契约 0 失败；未提交工作区提示 1 项，不作为已发布验收。
