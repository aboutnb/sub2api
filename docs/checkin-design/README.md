# 每日签到设计稿

`index.html` 是可编辑的高保真原型，页面底部控制器可切换用户端、管理端及主要业务状态。原型不依赖项目构建，可直接在浏览器打开。

## 固定画面参数

| 画面 | 查询参数 |
| --- | --- |
| 用户可签到 | `?screen=user&state=ready` |
| 幸运签到二次确认 | `?screen=user&state=luckyConfirm` |
| 用户已签到 | `?screen=user&state=success` |
| 用户功能关闭 | `?screen=user&state=disabled` |
| 用户功能关闭但今日已签到 | `?screen=user&state=disabledChecked` |
| 用户结果确认中 | `?screen=user&state=unknown` |
| 管理配置 | `?screen=admin&state=default` |
| 管理保存确认 | `?screen=admin&state=confirm` |
| 管理版本冲突 | `?screen=admin&state=conflict` |
| 管理配置损坏 | `?screen=admin&state=invalid` |

追加 `capture=1` 会隐藏设计稿控制器，用于导出评审截图。
追加 `date=YYYY-MM-DD` 可预览其他服务端自然月，原型会按真实首日星期和当月天数重排日历。

## 评审基线

- 用户快捷入口固定在 Header 余额金额之前，用户侧栏同时提供独立“签到”入口。
- 完整领取交互位于独立 `/checkin` 页面。
- 用户页采用参考项目的“紧凑渐变余额摘要 → 普通/幸运操作卡 → 当前自然月签到日历 → 签到记录列表”层级。
- 参考图中的下注输入和资金博弈不属于本版；签到前不展示余额金额或倍率，避免把视觉参考误读成业务承诺。
- 用户可直接点击普通签到；幸运签到先进行二次确认，倍率模式展示配置的可能倍率范围后才允许提交。
- 成功态展示实际余额、签到模式和到账时间；不展示并发、预算或“随机到账”。
- 未签到时 Header 快捷入口、顶部状态和两张模式卡统一显示“未签到”，不显示“今日可得”、刷新倒计时或连续天数。
- 签到记录使用参考项目的纵向记录样式，包含模式、时间、余额变动和余额前后值，并提供分页入口。
- 参考的 `xuya-dev/sub2api` 当前 main 签到实现包含每日唯一、普通/幸运模式、随机余额和历史记录；本稿按该逻辑对齐，不增加签到并发奖励。
- 管理端保持配置、今日概览、发放记录三个平级区域；全局、普通和幸运签到分别保留开关，幸运配置用分段控件切换“余额比例 / 固定金额”。
- 桌面基准宽度为 `1440px`，移动基准宽度为 `390px`。

## 路由边界

- standard mode 普通用户：Header 与侧栏入口均跳转 `/checkin`，页面与快捷入口复用同一份签到状态。账号冷却期内仍保留入口，由页内说明不可用原因。
- simple mode：不渲染 Header 快捷入口；访问 `/checkin` 重定向 `/dashboard`，全过程发起 `0` 次签到状态请求。
- 管理员：登录用户端后可使用签到快捷入口和 `/checkin`；管理配置仍仅从 `/admin/checkin` 进入。
